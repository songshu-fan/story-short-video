# 技术坑、已否方案与开发约定

## ffmpeg 9 的坑（本机 9.0.2，反复踩过）

| 坑 | 症状 | 正确做法 |
|---|---|---|
| `crop` 移除了 `eval` 选项 | 逐帧平移表达式失效 | 用 `zoompan`（表达式每帧求值）或 `overlay`（`eval` 默认 `frame`） |
| `-filter_complex_script` 已移除 | 报错找不到选项 | 用 `-filter_complex` 加图文件，或直接传字符串 |
| `zoompan` 没有 `t` 变量 | 时间表达式静默失效 | 用 `on/25`（帧号 / fps） |
| 静态图输入漏 `-loop 1 -framerate 25` | 滤镜图绑定失败、单帧流参数不定 | 每张图前都加这两个输入选项 |
| `loudnorm` 放在滤镜链尾 | 5.0s 被缩成 4.87s、语音提前 0.15s 结束 | 响度归一交给引擎 `build_audio()` 统一做，片头模块只负责对齐与留白 |
| `atrim=duration` 受 PTS/time_base 影响 | 总长不精确 | 用 `atrim=end_sample=240000`（5s×48k），并在 `adelay` 后 `asetpts=PTS-STARTPTS` |
| `silencedetect` 口径不一致 | 裁掉的尾音长短不同，对齐差 0.15s | 全链路统一 `noise=-38dB:d=0.12` |
| `displace` 需要 3 路输入 | 图绑定失败 | 已弃用，见下 |
| `-shortest` 不生效 | 音画长度不齐 | 显式 `-t` 让视频严格贴音频 |

## 素材坑

- **免费商用视频素材（Pexels/Pixabay/Mixkit/Coverr，零积分代替 VideoGen）的下载法**：网页能被浏览器看到，但裸 `curl` 网页常被 403；CDN 大文件 GET 常被代理掐断（HEAD 返回 200、GET 却 000/502）。两条实测有效的做法：① **反查真实直链**——`curl -I https://www.pexels.com/download/video/<ID>/` 看 302 的 `Location`，得到形如 `https://videos.pexels.com/video-files/<ID>/<另一个文件ID>_1920_1080_30fps.mp4` 的真实地址（注意文件名前缀不是视频 ID，猜 `<ID>-hd_...` 必然 404）；② **用 ffmpeg 直连 URL 分段读取**——`ffmpeg -user_agent "Mozilla/5.0" -i "<直链>" -t 12 -c copy out.mp4`，ffmpeg 走 HTTP 分段能穿透代理限制；4K 源可边下边 `scale=1280:720 -preset ultrafast` 直接压小，别存原片。下载后逐帧抽帧看有无现代建筑/公路/电线/人物/水印，猜 ID 会下到猫和海豹，必须看画面。授权与来源 URL 写进项目说明留痕。
- **动态镜替换掉的图片不能在滤镜图里留悬空节点**：`resolve_srcs()` 曾对 `images` 里**每一张**图都建 `[N:v]null[imgN]`，但当某镜从 `img:i` 改成 `motion:j` 后，那张图的 null 输出没有任何镜头引用，ffmpeg 报 `Filter 'null:default' has output 0 (img1) unconnected`。修法：先扫全部 `shots[].src` 收集真正被引用的图片索引，只为它们建 null 节点；命令行里仍保留全部图片输入以固定槽号不变。已修复，兼容旧篇（139 单图 / 098 img2 一镜两图回归通过）。
- 技能包**不内置动态素材**（默认 0 动态镜，对出片无用且要花积分）。若自行用 VideoGen 生成本篇动态素材：3:2 素材（如 1152x768）进 16:9 的 zoompan 前必须先 `crop=1152:648:0:120,scale=1920:1080`，否则横向拉伸 12%；这一刀同时切掉左上角「AI生成」水印。16:9 素材设 `crop16x9: false`。
- VideoGen 的 `reference_audios` 只接受**公网 URL**（本地路径、base64 都被拒）；`image` 与 `reference_audios` 不能同传，要用 `reference_images`。这两条只在重新生成片头口型视频时才相关。
- **ImageGen 生成的图片右下角固定带「AI生成 / WORKBUDDY」水印**：prompt 里写「不要文字、不要水印」无效，不传 `footnote` 也会有。零成本解法：从**顶部**取 16:9（`1536x1024` → `1536x864`，底部 160px 连同水印一起切掉），再 LANCZOS 放大到 `1920x1080`；只裁不拉伸，构图完整、人物不变形。裁完仍要抽帧复核四角，别只信参数。
- **2x2 分格出图省积分（实测，但默认不用）**：开工确认第 6 项默认「否」，即逐镜出单图、构图更可控；只有主人明确选「是」才用四格。`ImageGen` 出 `2048x1536` 的 2x2 四格图，每格 `1024x768` 从顶部裁到 `1024x576`（16:9）再放大到 `1920x1080`（1.875x）；四格彼此独立无格线，平台水印只在整图右下角、随底部裁切去掉。实测 1 张单图 + 3 张四格图共 **4 次出图覆盖 13 镜**（约 20~40 积分），比逐张 13 次省一半以上，但白边/串图风险高，必须逐格抽帧验收。
- **四格图偶尔被画成「白底上贴四条横幅」（009 篇踩到，非必然）**：ImageGen 不稳定，同一批 3 张四格图里可能只有 1 张四周留大片纯白（内容框如 `1000x516` 横条居中，而非满格 `1024x768`）。此时按「均分四格 + 顶部裁 16:9」会把白边带进成片，镜 2/3 出现上下大块白边。零成本解法：`cells()` 里对每格先用 numpy 找非白（任一通道 <245）像素的真实外接框 `content_box()`，只裁出内容区再交给 `to_16x9()`；满幅的格子外接框＝整格，行为不变。参考 `episodes/009/处理场景图.py`。**每次重裁后必须抽帧看四角**，不能只信参数；出图时也可在 prompt 强调「四格铺满整张画布、无白底无边框」降低发生率。

## 音频坑

- 本机**无 NVIDIA GPU**，也没有 torch / cv2 / onnxruntime，Wav2Lip 等本地唇形同步不可行。
- 旧式「固定视频流 + 换音轨」的口型是近似对不上（唇形按内置原句生成），**调参数救不回来，局部柔焦遮挡也被否定**。按「开工确认」第 2 项（仅横版有此项）：默认不生成口型时就用这条旧式换音轨路径出正式片（零积分、接受近似唇形，140/186/002 已如此）；用户要真同步时才给 `shots.json.head_video` 指向 VideoGen 按本篇音轨生成的专属口型视频，约 50–100 积分/篇，做法见 workflow.md，生成音轨与原音轨相关应 >0.9。别把旧式换音轨当成「禁止用于正式片」。
- VideoGen 的 `reference_audios` 不接受本地路径（报 `base64 audio is not supported`），必须先传临时公网链接；`reference_images` 可用本地路径锁人物，但不能与 `image` 参数同传。
- 片头音色与旁白同为 `zh-CN-YunjianNeural`，但**片头是固定角色，音色独立保留**，不要拿「和旁白统一」当好处。曾为填满窗口做 0.82x 减速，同一声音被拖慢 18% 后听感就变了，被用户指出后撤掉：现在默认不变速。
- 响度目标 -16 LUFS / TP -1.5；TP 曾测到 -1.53 贴顶，批量前建议用两遍 measured loudnorm 压回 -3。
- **edge-tts 服务端随机 `NoAudioReceived`**：与文本无关（同一句同一音色时好时坏，约 1/4 失败），本机时钟与网络时间一致也照挂；失败还会留下 0 字节 mp3。`series/new_episode.py` 的 `synth()` 已增量改为：稿子变化时清空旧分句 → 逐句最多 6 次重试 → 每句 `asyncio.wait_for(timeout=20)`（**不加超时时 WebSocket 会一直 hang，整批建篇被系统 SIGTERM 杀掉**）→ 空文件清理 + 体积校验 + 句间 0.4s 节流。成功路径行为不变。批量铺片时整批挂先查这个，别去改旁白稿，也别 sleep 死等服务端。
- 胶片颗粒破坏帧间压缩（含 displace 时 92MB，去掉并降 noise 到 4 后 65MB）。批量铺片前建议再降 noise 或调 CRF。

## 已经否掉、不要再提的方案

- **v8 的 displace 像素位移**：肉眼几乎看不出，判定为无效改动。
- **静态图上叠柔光雾 / 噪点亮斑**：前者帧差仅 1.0x（太柔＝看不见），后者帧差涨了但视觉是细碎颗粒、糊暗部，等于 v8 覆辙。结论：静态图上叠滤镜做不出「灵动」，必须有独立物体真位移（v12 用 16 枚浮尘光点）。
- **路线 C：VideoGen 图生视频做真动态镜**：约 50~100 积分/段，用户以「太贵」否掉。
- **一张底图反复切多镜、素材重复**：曾有用 3 张底图切 13 镜，换镜差异只有 5.5，补到 13 个独立素材后 25.2。用户两次因「图少、太单一」否版——否的是**素材重复**，不是「镜头数量少」。镜头数按旁白句数自定，6 镜、20 镜都可以，但相邻镜尽量给不同画面。
- **人物设定卡 / 参考图保一致性**：神话角色往往没有固定服饰，且参考图要花积分；唯一反复出现的是片头说书人，已用固定视频/参考图锁死。现有两套（古装 `host_rgba.png`+`talk_test.mp4`、现代 `host_modern_rgba.png`+`talk_modern.mp4`），**遮罩与口型视频必须同人同构图、不可混搭**；换说书人整套一起换。
- **现代说书人素材做法**：ImageGen 出半身正面像（深墨绿纯背景，1024x1536）→ 用该图作首帧 VideoGen 出 5 秒张嘴视频（`seconds=5`，无音轨）→ 遮罩不用精抠人像：口型视频自带背景，照古装做「左 x≈101 竖切 + 右侧贴边 + 顶部淡入 + 底部渐隐」的羽化矩形即可；两路都 scale 到 766x1080 对齐。左上水印由引擎 delogo 去掉。
- **宫殿/庭院/群臣背景全片复用**：对后世历史故事成立，远古神话不成立；应按题材建库。
- **30 秒说书人回闪**：用户要求去掉，正片完全无人像。
- **居中字幕**：v8 试过，用户要求回到下方居中（`Alignment=2`）。
- **柔焦遮挡嘴**：用户否定「遮挡嘴不是好办法」，已全部删除；走真同步，不走遮挡。
- **画面震动 / 手持微抖 / 开镜脉冲 / 逐帧胶片颗粒**：用户要求「图片不要左右震动，只留上下浮动」，复核后仍嫌震。现已把 zoompan 的 x、zoom、y 微抖、开镜 sin 脉冲、雾层 x、浮尘 x、逐帧 noise 全部去掉；只允许 y 做线性方向性平移。不要再加回任何随时间变化的抖动/缩放/颗粒。
- **上下浮动卡顿（zoompan 取整）**：只把抖动去掉还不够——`MOTION_SCALE=0.5` 时 1080p 每帧位移不足 1px，zoompan 按整数像素取裁剪窗，实测 230 帧仅 1 帧动 1px，看起来「卡住后跳一格」。修法是 `SUPERSAMPLE=3`：先在 5760x3240 上 zoompan，再 lanczos 缩回 1920x1080；`dx` 同比乘 3。降超采样倍数会立刻复现阶梯卡顿，别为省时间动它。
- **非统一画风 / 画面内文字字幕 / 人物正脸大特写**：用户明确要求统一为「写实电影剧照，电影级自然光，浅景深，写实历史剧质感，无文字，无字幕，避免人物正脸大特写」，并追加**环境句**「画面自带电影光影层次，拒绝过度干净、空洞廉价感，氛围感直接拉满」与**人物句**「自带原生真实肌理，保留毛孔、轻微细纹、自然瓷感，拒绝塑胶假面，还原真人原生皮肤」。这是图片内容的约束；成片字幕照常由引擎叠加，平台水印靠裁切。

## 用户明确的开发约定

- **增量开发**：每次只完成一个功能，不提前开发后续内容。
- **不重写已运行的代码**：已跑通的模块只做增量修改。
- **代码简单、注释清晰**。
- **版本目录独立**：每版单独目录，旧版一律不动。
- **未定版前只渲前几秒**：`--test 45` 约 43 秒出片。视频本身也可以做短，短＝更省钱也更灵动。
- 「灵动」的正确答案是**剪辑密度与画面内容**，不是滤镜数量。
- **剧本四段式固定的是功能顺序，不是句数**：① 3 秒钩子 → ② 背景起因 → ③ 核心冲突 → ④ 结局升华。别写成「每段固定几句」，也别把 `lines.json` 改成对象数组——TTS / SRT 链路只读纯字符串数组，四段归属放 `script.json`。
- **结尾针只在 ASS 里加事件**：片尾定帧卡用半透明绘图矩形 + 居中字卡实现，不动滤镜图；用 `drawbox` 做压暗会硬切闪一下。ASS 绘图矩形要 `\p1 … \p0` 包住、颜色是 `&HBBGGRR&`。`shots.json` 不带 `ending` 时必须与基础行为逐字一致。
- **验收片尾不要渲全片**：`--tail 8` 是独立轻量路径，ASS 事件时间必须整体减去偏移，否则字卡不会出现在预览片里。

## 引擎参数化的坑（改 shots.json 时）

- **数量不是硬结构**：镜头数 = 旁白句数；`images` / `motions` 任意长度、动态镜任意个（含 0）。
- **旧镜头表的 `[N:v]` 槽号与 images 下标差 4**：一律写 `img:i` / `motion:j`，引擎自动算输入槽；旧式写法仍兼容。
- **固定输入槽会随素材数量后移**：引擎按 `4 + 图片数 + max(0, 动态段数-1)` 计算 fog/talk/particles 等槽号，不要在滤镜图里手写 15~20。
- **解析后的标签必须带方括号**：`shot_chain` 用 `[img0]` 而不是 `img0`，否则 ffmpeg 会把标签当滤镜名报 `Invalid argument`。
- **没有动态素材时槽 1 用底图占位**：引擎仍保留该输入槽以固定后续编号，不进滤镜图，属正常行为。
- **3:2 动态素材必须 `crop16x9: true`**：16:9 素材要显式设 false，否则会被多裁一刀。
- **新故事沿用别的篇画面是最容易犯的交付错误**：把 A 篇的图放到 B 篇就是穿帮。建篇默认不填占位图，`images` 留空并标记缺图；引擎读 `status` 与 `images` 路径，含「占位」或指向内置占位目录时正式片/短版直接报错，`--test` 放行但打印警告。精简包已删除内置样例图，`--placeholder` 会直接报错、不可用——场景图必须用 `--images-dir` / `--images-paths` 给本篇画面。
- **片头不显示编号**：引擎已删除 `Num` 样式与 `NO.{id}` 字幕行，别再从旧版抄回来。

## 2026-11-18 新增踩坑记录

1. **ffmpeg 不在 PATH**（本机装在 `C:\ffmpeg\bin`）：引擎/建篇/校验脚本原先裸调 `ffmpeg`，会 `FileNotFoundError`。现在统一走 `runtime/series/ffpath.py`，遇到同类问题时先跑 `python -c "import ffpath;print(ffpath.report())"`，或设 `FFMPEG_BIN`。
2. **片头底图尺寸**：`head_image` 指到非 1920x1080 的图（本篇场景图多为 1536x1024）时，片头链与 xfade 尺寸不符，报 "First input link main parameters (size 1536x1024) do not match..."。片头链已固定 `scale=1920:1080:force_original_aspect_ratio=increase,crop=1920:1080`。
3. **分镜缓存的时间基**：缓存 mp4 的时间基可能是 1/12800，直接喂 xfade 会报 "timebase (1/25) do not match (1/12800)"。缓存输入统一先过 `fps=25,settb=1/25,setpts=PTS-STARTPTS`。
4. **缓存失效边界**：key 只含素材（路径+大小+mtime）、lens、时长、相位、运动参数、超采样与画质常量。改字幕、换片头底图、换音轨、改叠加层都不会重渲镜头——这是设计目标；但**改了 `MOTION_SCALE`、`SUPERSAMPLE`、镜头 lens 或旁白句数**，必须让缓存失效（参数已进 key，会自动重渲）。换素材文件同尺寸同 mtime 的极端情况不会失效，必要时删 `缓存/镜头/` 重来。
5. **QSV 画质**：`h264_qsv -global_quality 22` 出来的文件比 libx264 crf20 小约 65%，简单画面 SSIM 仍 0.994，但暗部渐变类画面有出现色带的风险。因此默认仍是 libx264；要用 QSV 建议先抽一帧暗部对比，必要时把 `global_quality` 调到 18~20。
6. **旧静帧混进归档**：`still_v12_*.png` 现在会在抽帧前清空再批量生成，避免上次多出来的帧被一起复制到 `成片/`。
7. **001 样板篇不能出片**：它的 11 张场景图（`v12/shot_01..09.jpg`、`v2/bg2.jpg`、`v2/bg3.jpg`）已随精简包移除；`still_v12_*.png` 是从成片抽的帧、带烧录字幕与标题，**不能当场景图用**。景别模板已移到 `runtime/series/lens_default.json`，`start_story.py` 不再读 `001/shots.json`。
8. **`--structure` 必须是 4 段**：`1,1,1` 会直接报错（四段各自句数，总和 = 旁白句数）。

9. **渲染污染 001 资产**：渲染任意一篇都会把 `vo_v12.wav` / `sub_v12.ass` / `still_v12_*.png` 写到引擎目录（`runtime/episodes/001/v12/`），覆盖 001 的原有产物。现在统一写 `episodes/<id>/_render/`，只有 001 自身（无 `--episode`）用引擎目录。若发现 001 的资产被改小/变了，从改前备份恢复即可（`_skill_backup/story-short-video`）。

## 画幅（9:16 竖版）的坑（2026-11-18 一期）

1. **字幕位置由「事件行的 MarginL/MarginR/MarginV」决定，不是样式**：ASS 的 `Dialogue` 行写死 `Body,,220,220,115` 时，样式里的边距被覆盖。第一版竖屏就是因为这行没参数化，字幕仍贴到画面最底部（抖音底部操作栏会压住）。已在 `sub_v12.ass` 生成处改为按 `FORMAT_SPECS[FORMAT]` 取边距（16:9 仍是 220/220/115；竖版 54/54/300）。
2. **重音句的 `\bord4` 与放大字号是另一套参数**：`accent_fs = 正文 × 50/46`（正文 54 → 59、竖版 48 → 52），改正文不会自动改它，但会一起变——调字号后务必抽一帧重音句看行距有没有跳。
3. **折行字数要跟着画幅和字号**：`wrap_cn` 的宽度不是"随便定"，算法是 `(w - 2*边距) / 字号`。当前横版 54 号 + 边距 220 → `(1920-440)/54≈27`，取 23 字留余量；竖版 48 号 + 边距 54 → `(1080-108)/48≈20`，取 18 字。**改字号必须同时改 `wrap`**，否则字一放大就顶到画框外。`wrap_cn` 只在标点处断行，兜底是 `width+2` 字强制断（v2.7.0 从 `+8` 收到 `+2`，就是为了防大字溢出）。
4. **把 16:9 场景图直接喂给竖版会放大发虚**：镜头链是 fill-crop（1920x1080 居中裁 607x1080 再放大到 1080x1920，约 1.78x），构图也只剩中间一条。竖版篇应出原生竖图（1024x1536），或至少接受「主体在中轴」的构图。
5. **竖版别排动态镜**：`crop16x9:true` 的段在竖版走 fill-crop，会切掉左右大半；要用就竖拍素材并设 `crop16x9:false`。
6. **说书人素材是 766x1080 竖条**，塞进 1080 宽会占掉 71% 画面，所以竖版一期直接不出说书人（`head.mode` 自动降级 `title`）；真要竖版说书人得另做素材，不在本期范围。
7. **画幅会影响分镜缓存**：缓存 key 含 `wh`，同篇切画幅会整批重渲，别指望复用横版中间片；调画幅时腾出渲染时间。

## 宫格出图（两宫格 / 四格）踩过的坑

1. **近方形图无法自动判版式**：`--panels 2` 只在宽图（≥1.2）判左右、竖图（≤0.85）判上下；2048x1536 这类 4:3 会直接报错要求 `--layout`，避免把四格图误切两半。
2. **格线/白边**：宫格图偶尔画成「白底贴两/四条横条」，按均分裁切会带白边。`split_panels.py` 已对每格做非白外接框检测（阈值 245），但内容占比 <55% 时会提示，必须抽帧看四角；提示词里加「两格铺满整张画布、无白边无格线」可降低发生率。
3. **两格人物串位/构图被切头**：宫格图每格是 4:3，裁 16:9 默认贴顶会切掉底部 1/4，主体太靠下就丢脚。生成时要求「主体偏上、下方留白」，或用 `--anchor center`。
4. **水印位置随版式变**：整图水印通常在右下角，两宫格只有右下那一格会带，裁完若仍在，那一格单独重出或用 `--pad` 外扩后再裁。
5. **切出的文件别和原图混在一个目录**：`场景图/` 只放切好的 `<原名>_pNN.jpg`；宫格原图放 `原图/`，否则 `fill_shots.py` 会把整张宫格当单镜图。
6. **镜数对不上**：切出张数少于镜数时 `fill_shots.py` 会循环复用，画面会重复；补宫格图后重跑切分即可（同名会覆盖）。
7. **一镜两图 + 宫格：格数与镜数不是 1:1**（2026-11-18 修正口径）：一张两宫格的**两格同属一个镜**（前半格 + 后半格，中间 0.3s 溶解），一张四格覆盖 2 镜；只有「一镜一图」时才是两宫格=2 镜、四格=4 镜。算张数用「总场景图 = 镜数 × 每镜图数，宫格张数 = 总数 ÷ 每张格数」。切出的 `p01…pNN` 是全局序号不是镜号，填图时加 `--pairs`（镜 k → `img2:2k,2k+1`、自动跳过动态镜），**不加就是顺序填 `img:i`**：镜 0 拿 `p01`、镜 1 拿 `p02`，两镜各半张、后半镜全丢（表现为「每镜只有半幅画面」或相邻镜画面接得上）。

## 一镜两图（`img2:i,j`）与分镜缓存（2026-11-18 修复）

**症状**：开了 `--cache` 后，一镜两图的镜头里前后半镜是**同一张图**，看不出切换；不开缓存则正常。

**根因**：完整滤镜里的两半镜用主图标签拼（`[img2]` / `[img3]` 这类），而缓存路径把每镜丢给一个只有 `0:v` / `1:v` 两路输入的独立 ffmpeg 进程；`[img2]` 没定义，ffmpeg **不报错**、按顺序解析成输入 0，于是两半镜都吃到第一张图（实测 `[img2]null[x]` 双输入 exit 0）。

**修法**：缓存分支改用真实输入标签 `0:v` / `1:v`；`ai==bi`（两张图索引相同）时打印中文告警；cache key 增加 `"gv": GRAPH_VERSION`（`GRAPH_VERSION=2` 定义在 `ENCODER` 之后），滤镜图口径一改，旧缓存自动失效。

**复核口径（别只看一帧）**：切镜点后 0.5s 内还在 0.8s 交叉溶解里，抽在那里看不出问题。要在**前半段中段**、**后半段中段**各取一帧，比主体区（去掉下方字幕带）灰度平均绝对差：真切换 >20，只有 2~8 说明第二张没生效。同镜可能有修复前后两份 hash 文件，**按 mtime 取最新那份**，否则会复核到旧缓存得出「9/15 疑似同一张」的假结论。

## 片头/封面专属图的坑（一张 16:9 横图两用）

1. **片头借场景图必撞镜**：片头底图若取自 `场景图/`，正片里必然有一镜和它一模一样。已改为每篇单独出一张 16:9 横图（见 workflow.md「片头/封面专属图」），`head_image` 指 `片头图/head_16x9.jpg`。
2. **与说书人撞脸撞色**：说书人是暗红袍正面像；片头图里若也是「红袍 + 正面/侧脸」，成片开头就是**两个红衣明代男人并排**，观众读成双主角。必须换成**背影或侧后、袍色区分**（本篇用深青袍背影才成立）。
3. **只给半身大头 → 封面裁成「脑袋+胸口」**：封面是 2:3 竖条，从横图纵裁只能取到中间那一竖。出图必须写「中远景、全身或大半身、人物高约占画面 55%~70%」，否则裁出来没有场景、也没法放标题。实测 1920x1080 的「上半身特写」纵裁后只剩头部与肩膀。
4. **横图直接用会带上平台水印**：ImageGen 水印固定在右下角，横图整幅做片头就露出。`head_cover.py` 默认从底部裁 6% 再去取 16:9（只裁不拉伸），水印位置不同就调 `--trim-bottom`。
5. **片头图主角太居中会被说书人挡住**：引擎把说书人贴右侧（x 约 101 竖切、右侧贴边），右侧 1/3 是「说书人位」。生成时让主角偏左、右侧留天空海面。
6. **纵裁锚点要跟着人物走**：`--cover-x` 默认 `0.30`（配「人物偏左三分之一」）；裁出来人偏了就往对应方向调，别硬用 0.5。
7. **每换一次片头图都要重刷两处**：`shots.json.head_image` 与 `导演稿.md`（`new_episode.write_director_doc`）；重渲只走缓存命中，几十秒完成，但 `_render/项目说明_v12.json` 的 `changes` 会被引擎重写回通用文案，记得再改回本篇说明。

## 人物一致性（有主角的篇最容易翻车）

1. **每镜一张脸 = 每镜一个新人物**：不锁参考图时，模型每张图都自由造脸。把人物铺满全部镜头，观众读成「十五个不同的人在演一个人」，比人物只出现四五次更糟。**判据不是「有人率」，是「同一个人率」**。
2. **零成本解法是造型锚定**：全篇一句固定 `cast` 锚定句（袍色、头饰、腰带、身形、年龄段），并多用**背影/侧后/剪影/手部器物**——脸不一样也不出戏。正脸只在每 3~4 镜给一次。
3. **参考图/设定卡花积分且易翻车**：要一张张传同一参考图，跑偏时生成「既不像参考也不像原人物」的混合脸，成本高。技能里仍不默认做，除非用户明确要求。
4. **跨年龄段/换装必须分段锚定**：少年粗布、为官蟒袍、晚年旧袍各一套锚定句，按段落切换；一句话通吃会出现「年龄忽大忽小」。
5. **抽帧验收要看人，不只看画面差异**：抽 3~4 帧有人物的镜头并排看袍色/头饰/身形是否一致，比量像素差更能发现穿帮。

## 一镜两图（`img2:i,j`）与分镜缓存

**2026-11-18 已修复：`--cache` 下第二张图被吞，整镜只播第一张。**
`build_shot_cache()` 曾把 `<分辨率>img{a}` 这类主图过滤标签直接传给单镜 ffmpeg 的 `shot_chain()`，而该进程只有 `0:v` / `1:v` 两路输入、没有 `imgN` 输入节点——ffmpeg 会静默落到第 0 路，两段吃同一张图，`xfade` 自然看不出切换。修法：缓存路径改用真实输入标签 `0:v` / `1:v`（非缓存路径仍是主图里的 `imgN` 节点，逐字不变）；同时 key 里加 `GRAPH_VERSION`，滤镜图结构一改就让旧缓存失效，避免「修了却看不出变化」。

自查口径：**别在切镜点后 0.5s 内抽帧**（那里还在 0.8s 交叉溶解里，看起来「两张一样」是正常的）。正确做法是在「前半段中段」和「后半段中段」各抽一帧比主体区像素差：该镜内部确实切换时应 >20，只有 2~8 说明第二张没生效。同时按文件名成对比较 `场景图/*_p01/_p02` 也能反查是素材本身重复还是引擎没吃到第二张。

## 2026-11-19 现场踩坑（已修 / 已记）

1. **竖版两宫格直接喂横图会拉伸变形**（已修）：`split_panels.py` 原先 `TARGET` 固定 `1920x1080`，竖版篇切出来还是横图，塞进 9:16 渲染只能 fill-crop，主体被切、画面被拉。现加 `--format 9:16`：每格**居中取宽**裁 `576x1024` → 放大 `1080x1920`。配套规矩：宫格画布必须用**横版**（`1536x1024`，左右两格各 `768x1024` 竖构图、主体压中轴、上下留余量）；竖画布上下叠两格脚本会拒绝（那是 4:3 横构图，切 9:16 必切没主体）。
2. **ImageGen 爱在场景里"自己加字"**（记）：座位牌会画出中文"座位牌"，既违反无文字约束，又和引擎字幕打架。提示词里的"无文字"挡不住，必须**提前换无字道具**：座位牌→空白卡+模糊色块、牌匾→只留浮雕、书页→留白/墨迹虚化，再加一句「画面中不得出现任何文字、字母、数字、字符、招牌字迹」。出了字只能重出＝多花积分。
3. **重出图打乱映射**（记）：`fill_shots.py` 按**文件名排序**取图，重出的图若带时间戳命名，排序一乱就和镜号错配，且**不报错**。规矩：出图前把「时间戳→镜号」映射钉进 `导演稿.md`；宫格命名按镜号打头（`s07_饭局.png`）；重出图另存 `重出/`、命名 `s07_饭局_v2.png`，切完用 `--images` 按镜号顺序显式传入。
4. **ffmpeg 假警报 `Cannot allocate memory`**（记）：渲测试片时终端报错，看着像中断，其实 `_render/` 下的片子已经写好（收尾阶段分配失败）。**先看产物**：`_render/` 有无 mp4、`ffprobe` 查时长与流数，确认没问题就不要改 `--ss` / `--cache` 参数重渲。
5. **`fill_shots.py --images-dir` 相对路径失败**（已修）：原先裸用 `Path(dir).iterdir()`，按**当前工作目录**解析，和 `--images` 的「按本篇目录解析」是两套口径，报错也只打相对路径。现统一为「先按本篇目录、再按当前目录」兜底，并在报错里打印**绝对路径**与两个候选基准。
6. **顶部卷名/篇名被当成 bug 查**（记）：`make_v12.py` 704–710 行把 `系列名 · 卷名`（`Vol`）和篇名（`Title`）从 `0:00` 挂到片尾卡前，是引擎的**常驻角标**设计，不是字幕错位。`shots.json` 无开关；想去掉必须改引擎，须先经主人同意，且保证默认行为逐字不变。
7. **动态素材复用比静态复用显眼得多**（已改 v2.4.0）：静态图重复能靠景别/裁切/镜像藏，真动态一复用就是“同一段视频又放了一遍”。引擎本来支持复用（`resolve_srcs()` 780–830 行 `split=N` + 各镜 `phase`），但**技术上支持不等于观感应成立**。`fill_shots.py --dynamic-at` 现改为**严格一镜一素材**：动态镜多于素材段直接报错、列出要改回静态的镜号；只有 `--reuse-motion` 放行两种例外（同一动作拆相邻两段 / 环境连续体延展），且 phase 改成**顺序相接**（按 `caption.srt` 句长累加，不再 1.5 秒等距乱铺），phase 逼近素材尾部会告警（等于从头重放）。
8. **动态镜上再叠引擎浮动＝双重运动**（已改 v2.4.2）：素材本身带运镜，旧的 `shot_chain()` 对 `is_motion` 没有任何分支，照常加 y 平移、照常走 3x 超采样——成片表现为“飘、晕、缝合感”，还白糊一遍清晰度。现动态镜走独立分支：不位移、不超采样，只取帧/裁 16:9/压暗/镜像/定时长。实测同一张静帧做的素材视频，动态镜两帧主体区差 **1.29**（只剩浮尘雾层与压缩噪声），静态镜默认浮动是 **6.44**——位移已彻底移除。
9. **横移别当默认**（v2.5.0 可选档）：字幕是横排的，背景横向移动会和“读字”抢注意力；纵向浮动与文字方向垂直、冲突小。所以 `pan_x` 只做远景/空镜、幅度 ≤0.3（约 2~3% 画宽），近景人物镜改用 `zoom` 缓推。
10. **`auto` 运镜只认 `note` 标签**（v2.6.0 起，v2.7.0 起是默认行为）：判定输入就是 `note`/`beat` 的文字，`note` 写含糊会同时命中多类关键词，结果不可控。统一用「【景别·主体】正文」开头（`【远景·海上船队】…`、`【特写·手部器物】…`、`【空镜·雪后宫墙】…`）。另外三条节奏约束会自动改 `auto` 镜：同向横移最多 2 连、每 5 镜强制一镜 `hold`、末镜豁免并优先拉远——**看到某镜莫名变成 `hold`，先想这条**，不是 bug。
11. **不写 `move` 也是 auto**（v2.7.0 口径变更）：老篇重渲时画面会从「纵向浮动」变成横移/缓推，别当成渲染出错。想保持旧观感，给这些镜写 `{"move": {"auto": false}}`；想固定就写显式 `type`。开工时打印的那行 `[运镜] 镜0 pan_x 0.25 left | 镜2 hold | …` 就是全篇实际映射，**先看这行再渲**，能省一整轮重出。
12. **新建篇的 `note` 是占位文本，auto 判不出东西**（v2.7.0 起默认 auto 后的副作用）：`start_story.py` 建的镜 `note` 一律是「本篇画面，待按情节补写提示词」，没有「【景别·主体】」标签，于是全片都命中兜底 `zoom 0.03 in`——六镜全是同一个缓推，看起来"运镜没生效"，其实生效了。填图时把 `note` 改成 `【远景·船队】…` / `【特写·手部】…`，再渲就有区分。
13. **稿检硬伤会直接拦住建篇**（v2.8.0）：`start_story.py` 在写任何文件之前跑 A 层规则，命中 emoji / `**` / 弯引号 / 半角破折号 / 套话就退出，`episodes/<id>/` 都不会创建。这是设计行为，不是脚本崩了；改稿重跑，别用 `--skip-ai-check` 硬闯（那些字符会进 TTS 与字幕）。想单独先看报告：`python scripts/check_ai_patterns.py --lines <稿子> `，退出码 1＝有硬伤。
14. **「画面整体滞后一句」＝宫格出图错开一格，重渲无效**（v2.9.0 记）：成片看着像引擎错位、缓存错位、音频滞后、槽号错乱，其实根因在**图片里**——同一张宫格里两格的提示词与旁白句序错开一格，出图模型照各自提示词作画，错配就固化成了像素。切图只认版式/外接框、填图只认文件名与 `--images` 顺序、引擎只认 `src` 下标，**三道环节都不校验语义**，所以一路静默到成片才暴露。排查顺序：① 对照 `宫格对照清单.md`（`panel_map.py` 生成）看镜号与旁白是否逐行咬合；② 打开宫格原图逐格读内容，看这一格画的是上一句还是这一句；③ 只有确认图对了才去查渲染侧。像素比对（灰度近邻/边缘相关）**不能判语义对错**：宫殿/城垣/船队这类相近场景差异可能很大，语义却对错了句。修法只有一个——**重出那张图**（图名带镜号，切完用 `--images` 显式传序），别用 `--no-cache`、换编码、改滤镜做无用功。
15. **填图后别只看"有没有图"，要逐镜读旁白**（v2.9.0）：`fill_shots.py` 现在会把「镜号 | 旁白句 | 画面 note」并排打印，并自动刷新 `宫格对照清单.md`；`panel_map.py --check` 对缺图、`src` 越界、`note` 仍是占位文本直接退出码 1。**跳过这一步**，语义错配就只能等成片抽帧才发现，代价是一整轮排查。
16. **句数放宽到 30 ≠ 切 30 个碎句，也不等于 30 张图**（v2.11.0）：上限 30 句是给「故事信息多」的篇放行，不是给句子放水——单句仍 16~22 字，写完逐句看有没有独立画面信息，只补情绪的句并回上一句。成本上：30 镜一镜一图、两宫格 = **15 张宫格图**，开工就要按这个数报预算；临时改成四格=8 张、一镜两图=30 张，别边出边算。
17. **「换一版」别重出图**（v2.11.0）：旁白文案确认答「换一版」只重写 `lines.json` 与 `--structure`（钩子换轨道/冲突段重排/换金句）；**句子数变了才需要补图或改 `src` 映射**，句意没变的老图照旧用。先重出图再改稿＝白花一轮积分。上限两版，第三版先问用户是不是换选题。
18. **`set_titles.py` 两种写法别混**（v2.11.0）：三段是「标题|核心思想|描述」，两段会按「标题|描述」处理、核心思想留空——**描述里想写 `|` 就别用两段式**，会被当成核心思想。脚本只做 `split(sep, 2)`，描述内部再出现 `|` 不会切断。
