# 完整工作流与命令参考

## 工作目录与目录契约

工作目录由环境变量 `STORY_ROOT` 或命令行 `--root` 指定，两者都没有时用当前工作目录。引擎与素材在**技能包内** `runtime/`，不依赖工作目录的具体位置。

```
<技能目录>/
├── runtime/                       # 自包含运行时（可整体移植）
│   ├── series/template.json       # 复用规范（画风/字幕/片头/剪辑/音频）
│   ├── series/new_episode.py      # 一键建篇（TTS → 时间轴 → SRT）
│   ├── series/head_voice.py       # 片头音轨按篇生成 + 音色自检
│   └── episodes/001/              # 内置素材（片头/底图/引擎），无动态素材、无样例场景图
│       └── v12/make_v12.py        # 渲染引擎（唯一入口）
├── scripts/                       # check_env / start_story / check_ai_patterns / panel_map / fill_shots
└── references/                    # workflow / shot_schema / pitfalls / copywriting / anti-ai-check

<root>/                            # STORY_ROOT 指定的工作目录
└── episodes/<id>/                 # 每篇专属（id 为编号或短名）
    ├── meta.json  lines.json  script.json  shots.json
    ├── caption.srt  vo.wav  vo/  head_voice.wav  导演稿.md  宫格对照清单.md
    ├── 场景图/                    # 任意张数本篇图片
    ├── 片头图/                    # head_16x9.jpg（片头底图）+ cover_2x3.jpg（封面底图）
    ├── 片头口型/                  # 本篇专属口型视频
    └── 成片/                      # 正式片 + SRT + 逐镜静帧 + 项目说明（v2.9.0 自动归档）
```

## 开工确认（先问再干）

接到出片请求，**先问「是否直接生成成片？」**：答「是」→ 按推荐值一次做完、不再逐项打扰（把采用的值复述一遍）；答「否」→ **逐项确认，且每一项都要用户明确回答**，推荐值只是参考、不许代答，缺项追问，答齐才动手。确认项及推荐值见 `SKILL.md`「开工确认」，**顺序是「先画幅、后文案、再片头」**：① **画幅—横版 16:9（推荐）/ 竖版 9:16** ② **旁白文案**（**稿子写完才问，不在开工时一起问**）—**可以（默认，直接建篇）/ 换一版（同选题重写全篇，上限两版，第三版先问换不换选题，只改 `lines.json` 与四段划分、已出的图不重出）** ③ 片头形态（**横竖版都问**，v2.11.5 起）—横版给 **无人像标题卡（C，推荐）/ A 说书人口播·内置口型 / B 说书人口播·真口型 / D 无片头**，竖版只给 **C 标题卡 / D 无片头**（竖版永远不出说书人）④ 45 秒测试—不渲（推荐）⑤ 动态镜—0（推荐）⑥ 每镜图片—1 张（推荐）/ 2 张 ⑦ 出图方式—**两宫格（推荐，出图次数减半）/ 单图（最可控）/ 四格（最省、风险最高）** ⑧ 生成物逐批确认—不确认（推荐，靠抽帧验收）。把用户逐项回答的值在对话中复述留痕并写进 `meta.json.confirm`，覆盖下文默认写法。**本篇场景图与片头/封面专属图都必须花 ImageGen 积分生成、不可省、不列入确认项**：没图引擎只许 `--test` / `--tail`，出不了正式片。**选 D 无片头也不例外**——那张横图改作封面源图（`head_cover.py --cover-only`），否则三平台封面没图。
**导演稿已退出确认链（v2.11.0）**：它照旧自动生成、随时可查，但不再是「要不要先过目」的确认项——审稿节点前移到旁白文案（第 2 项），改稿零成本，别等到图都出完才审。

## 开工顺序（按开工确认：画幅先行、文案第二、片头第三）

1. **先定画幅**（开工确认第 1 项，默认横版）：`start_story.py --format 9:16` 建竖版篇；竖版片头**不出现说书人**（选了 A/B 时引擎自动改 `head.mode=title`、口播照旧保留；选 D 则整段都不要），字幕按竖屏安全区重排。**这一步必须在出图之前**——画幅决定裁切取景框（横版裁 16:9、竖版裁 9:16 或直接出竖图）。分镜、旁白、四段结构与横版完全一样，只是画幅和版面换了；同一篇可出横、竖两版（两套渲两套出图，成本翻倍，默认只做用户要的那版）。
2. **写稿 → 旁白文案确认（开工确认第 2 项，稿子写完才问；直接在对话里输出，不落文件）**：四段区间 ①钩子 1 ②起因 3~8 ③冲突 5~20 ④升华 2~4、**全篇 ≤30 句**；写完先过 `copywriting.md` 自检（含「沉重的历史感」8 条）与 A 层去 AI 味体检，然后把文案**直接打在对话里**给用户——四段各几句、每句原文、钩子走哪条轨、末句金句，一屏给完。**这一步不生成任何文件**：不写 `lines.json`、不出 txt/md 稿、不甩附件（`lines.json` 等用户点头、`start_story.py` 建篇时才落盘）。答「可以」→ 建篇；答「换一版」→ 同选题在对话里重写重发（钩子换轨道／冲突段重排／换金句），上限两版，第三版先问「是不是换选题」，已出的图不重出。**别把整份导演稿甩给用户审——那是一屏看不完的东西。**
   `导演稿.md` 在建篇与填图后**自动生成**（镜号/四段归属/旁白/素材/运动/画面备注全表 + 片头、结尾针信息 + **「发布候选」三组「标题＋核心思想＋描述」**；`new_episode.write_director_doc`，零积分，可随时重跑刷新），**不参与确认**，随时可查。发布候选由 `scripts/set_titles.py` 写进 `script.json.titles`（标题默认＝篇名、核心思想 15~25 字、描述 60~120 字），没写时该段保留占位提示。
3. **生成本篇场景图（必做、花积分、无需确认）**：场景图是本篇的硬性投入，不列入开工确认、不必再征得同意。**每张图的提示词固定三段串，顺序不能乱**：① 基底句「写实电影剧照，电影级自然光，浅景深，写实历史剧质感，无文字，无字幕，避免人物正脸大特写」→ ② 环境句「画面自带电影光影层次，拒绝过度干净、空洞廉价感，氛围感直接拉满」→ ③ 人物句（**有人物的镜必带**）「自带原生真实肌理，保留毛孔、轻微细纹、自然瓷感，拒绝塑胶假面，还原真人原生皮肤」；之后接该镜剧情（宫格图每格同此三段）。**有人物的篇再固定写一句「人物锚定句」**（造型锁死、跨图不变，模板见下「主人翁出镜节奏」），写在风格串之后、情节之前。「无文字/无字幕」只指图片内容，成片字幕由引擎叠加、照常保留；平台水印不靠提示词，仍按裁切去掉。**默认两宫格（开工确认第 7 项，出图次数直接减半）**：横版画布 `2048x768`，左右两格各 `1024x768`，每格顶部裁 `1024x576` → 放大（1.875x）到 1920x1080；提示词写「画面横向均分为左右两格，无格线无边框」+ 左格/右格各一句情节，切图一律走 `split_panels.py`（竖版加 `--format 9:16`，画布仍用横版）。**代价要说清**：两宫格失败率高于单图（格线、白边、两格人物串位、格内太满裁切切头），一次废两张；**一镜两图时两格同属一镜**（前半格＋后半格），提示词要写「同一镜的两个瞬间」，不能写成两个不同情节。要最可控选单图（`1536x1024` → 顶部裁 `1536x864` → 放 1920x1080）；竖版单图出 `1024x1536` 原生竖图（或 `1536x1024` 居中裁 `576x1024` 再放大，会发虚）。最省选四格（**`2048x1152`**，每格 `1024x576` 原生 16:9；v2.11.4 起，旧 2048x1536 有 315 万像素、跨 261 万档位线会翻倍），四格无格线、串图与白边风险最高，必须逐格验收。可照此写一个本篇的「处理场景图.py」统一裁切。**裁切脚本要对每格做 `content_box()` 非白检测再去白边**（四格偶尔被画成白底横条，见 pitfalls.md），裁完抽帧看四角确认无白边/黑边。图片/动态素材生成完后是否先交用户过目，按开工确认第 8 项执行（默认不确认，生成完直接进第 3 步）。**数量怎么算**：场景图总数 = 镜头数 × 每镜图数（开工确认第 6 项：一镜 1 张 / 一镜 2 张）；出图方式只决定一张图装几格（单图 1 / 两宫格 2 / 四格 4），宫格张数 = 总数 ÷ 每张格数（向上取整，余下当备用）。**30 句上限的篇按两宫格算 = 15 张**（30 镜 × 1 图 ÷ 2 格），先按这个数预算再决定要不要一镜两图。**图要均匀铺满全片**：宫格按连续镜段推进，同一张宫格不许隔段乱插；图多于镜数只取前 N 张、余下备用；图少于镜数由 `fill_shots.py` 按等间隔复用（重复散在全片，不堆在片尾）。**一镜两图时宫格的格要成对给同一镜**（镜 0=`p01+p02`、镜 1=`p03+p04`…，`src` 写 `img2:0,1` / `img2:2,3`），填图时加 `--pairs` 由 `fill_shots.py` 自动配对（跳过动态镜、不为动态镜消耗图；图片不足会告警并等间隔复用）。不加 `--pairs` 才会按顺序填 `img:i`，相邻两格被分给相邻两镜＝串镜。

### 主人翁出镜节奏（有人物的篇默认按此做，不必逐篇确认）

观众认的不是「每张都有脸」，是「每张都是同一个人」。没有参考图/设定卡锁人物时，**靠造型锚定 + 景别轮换**替代：

| 规则 | 做法 |
|---|---|
| 造型锚定句 | 全篇固定一句，建篇时 `start_story.py --cast "郑和=同一人物：<袍色/官服>、<头饰>、<腰带>、<身形>、<年龄段>"` 写进 `shots.json` 的 `cast`，写每镜提示词时前置。锁的是造型，不是脸 |
| 出镜率 | 主人翁出镜约 **50%~70%**：不是每镜都塞人（同机位重复、切换感消失），也不要只出现两三次（变成风光片） |
| 景别轮换 | 远景（人小、交代规模）→ 中景背影/侧后（交代态度）→ 近景手部器物（交代动作）→ 每 **3~4 镜**才给一次看得清正脸的镜（仍不做正脸大特写） |
| 未出镜的镜 | 用他的**行动痕迹**承载因果：船队、奏报、金锭、空船坞、被翻过的海图 |
| 一镜两图 | 两格**至少一格有人**（一格人物 / 一格环境·对手·器物），零成本把出镜率拉到 70% 左右，还自带切换感 |
| 跨年龄段/换装 | 一句话通吃不了，按段落给 **2~3 套锚定句**，否则造型会莫名切换 |
**建篇前稿检（必过，v2.8.0 起）**：旁白稿先过 A 层体检，有硬伤不许建篇。

```bash
python <技能目录>/scripts/check_ai_patterns.py --lines my_lines.json --format 16:9   # 退出码 0 才继续
python <技能目录>/scripts/check_ai_patterns.py --lines my_lines.json --fix-quotes     # 弯引号换「」
```

- 硬伤＝emoji、`**`/markdown 残留、弯引号、半角 `-` 当破折号、半角标点混中文、A 层套话关键词；提示＝单句字数（横 22 / 竖 18）、破折号堆砌；
- `start_story.py` 建篇时会再跑同一套规则，硬伤直接退出（不给 `--skip-ai-check` 不会写任何文件）；
- B 层（三项排比、称呼统一、情感标签、假范围）与 C 层（判断锋利度）机器判不了，按 `references/anti-ai-check.md` 人工过。

4. **再建篇/渲染**：图就位后先按题材判断说书人（**横版才有意义**：古代/神话/历史→`--host ancient` 默认，近现代/当代/现实→`--host modern`，见 SKILL.md「说书人选择」；竖版片头无人像，`--host` 不影响成片），再 `start_story.py --images-dir` 建篇——`head_image` 自动取中间那张本篇图作片头底图（避开首镜钩子与末镜收束，不额外生成片头图；`fill_shots.py --head-image` 可换）；片头口型按开工确认第 2 项——**仅横版**、选「生成」才做本篇专属 `head_video`（见下，此时音画同源），默认「不生成」则沿用内置固定口型只换音轨（接受近似唇形）。

## 画幅：横版 16:9 / 竖版 9:16（2026-11-18 一期）

| 项 | 16:9（默认） | 9:16 |
|---|---|---|
| 成片 | 1920x1080 | 1080x1920 |
| 片头 | 四形态可选：A/B 说书人（`head.mode=host`+`head_video`）、C 标题卡无人像（`title`）、**D 无片头（`none`）** | **只能 C 或 D**：标题卡压片头图 + 保留口播（引擎把 host 降级 title），或整段不要 |
| 正文/篇名/卷名字号 | 54 / 66 / 34 | 48 / 56 / 28 |
| 正文边距（左右 / 底） | 220 / 115 | 54 / 300（避抖音底部操作栏与右侧点赞栏） |
| 片尾金句 / 落款 | 58 / 26 | 46 / 22 |
| 出图建议 | 单图 1536x1024 顶部裁 16:9 | 单图 1536x1024 居中裁 9:16（或直接出 1024x1536 竖图后居中裁），主体放画面中轴 |
| 动态素材 | 原规则 | 不建议排；必须排就用竖拍素材并设 `crop16x9:false` |

- **建篇**：`start_story.py --format 9:16`，写进 `shots.json.format`；引擎按篇生效，命令行 `--format` 可临时覆盖。
- **片头/封面图**：横版篇照「一图两用」（2048x1152 横图 → 片头 + 纵裁 2:3 封面）；**片头形态 D（无片头）时改用 `head_cover.py --cover-only`**，只出 2:3 封面、不出片头底图；**竖版篇改出竖图**（1024x1536，人物中远景、主体在中轴、上方留片名位），直接当片头底图（引擎居中裁 9:16）与三平台封面来源，不再用 `head_cover.py` 横切（竖版 D 时只取封面部分）。
- **一套图双格式**（本次一期的成本原则）：同一张 `1536x1024` 单图既能裁 16:9，也能居中裁 9:16（1024 高裁 576 宽），所以**竖版篇不必重新出图**，只要在裁切时改取景框；但两次裁切不能共用同一批 `场景图/`（尺寸不同），竖版另建 `场景图_竖/`，或干脆按竖版单独出图。原生竖图（1024x1536）画质最好，16:9 图纵裁会放大发虚、两侧构图被切。
- **验收**：竖版必须抽三帧看**字幕是否被底部 UI 遮住**、片名是否在安全区内；片尾卡要单独 `--tail 8` 看金句居中不贴边。
- **分镜缓存**：key 含 `wh`，从横版切竖版会重渲全部镜头；反之亦然。

## 三条渲染命令

在 `<技能目录>/runtime/episodes/001/v12/` 下执行：

```bash
python make_v12.py --episode "<root>/episodes/<id>/shots.json" --test 45   # 前 45 秒验证片
python make_v12.py --episode "<root>/episodes/<id>/shots.json" --tail 8    # 只渲片尾针 8 秒预览
python make_v12.py --episode "<root>/episodes/<id>/shots.json" --sec 30    # 30 秒正式短版
python make_v12.py --episode "<root>/episodes/<id>/shots.json"             # 全片
```

- `--test N` 只渲前 N 秒，约 10 倍提速；输出 `test_v12_<id>.mp4` 在引擎目录，**提前返回，不生成正式片、静帧与项目说明**。
- `--tail N` 只渲片尾定帧卡（N 是上限，缺省 8 秒，实际按卡窗口收紧到约 4 秒），输出 `tail_v12_<id>.mp4`：中性暗底 + 真实 ASS 字卡，几秒出片，专门验收结尾针，不渲全片、不生成正式片。**ASS 事件时间要整体减去偏移**，否则字卡不会出现在预览片里。本篇素材仍是占位图时预览自动改用中性暗底，不把第 001 篇画面当成品展示。
- 无 `--test` / `--tail` 时才走正式流程：成片 `《标题》.mp4` 写到 `episodes/NNN/成片/`，文件名就是主题名，不加任何风格后缀；短版加 `_短版N秒` 以免覆盖全片。同时写同名 `.srt`、逐镜静帧 `still_v12_NN.png`、`项目说明_v12.json`。**静帧与项目说明 v2.9.0 起自动落到 `成片/`**（`changes` 可由 `meta.json.changes` 覆盖）；只有不带 `--episode` 的 001 回归才落在引擎目录。
- 不带 `--episode` 则渲染引擎内置素材的默认路径，用于回归复核；注意它会覆盖 `test_v12.mp4`，复核前先备份交付过的测试片。
- 加 `--format 9:16` 可临时按竖版渲（不改 `shots.json`），用来对比同一篇的横竖两版；`shots.json` 已写 `format` 时以文件为准、命令行显式给的优先。**切画幅会整批重渲镜头**（缓存 key 含宽高）。

## 出全片后的归档与校正（v2.9.0 起自动，这里只做校正）

正式出片（无 `--test`/`--tail`）时引擎会直接把逐镜静帧 `still_v12_NN.png` 与 `项目说明_v12*.json` 写进本篇 `成片/`；`_render/` 里不再留需要手工复制的东西，旧版残留会被清掉。

```bash
# 只有 001 回归（不带 --episode）才落在引擎目录，仍需手工归集
cp <技能目录>/runtime/episodes/001/v12/still_v12_*.png <root>/episodes/<id>/成片/
```

`项目说明_v12.json` 的 `changes` 默认已是当前实况（自动运镜、字号折行、3x 超采样等），要写本篇说明就在 `meta.json` 加 `"changes": ["…", "…"]`（3~4 条），下次出片引擎用它覆盖，不再需要手改 JSON。之后抽帧复核片头（无 NO. 编号）、后段画面与片尾定帧卡。ImageGen 出图右下角带水印，换篇前统一从顶部裁 16:9 去掉（见 `references/pitfalls.md`）。

## 画面情节与旁白句对位（v2.9.0 起必做，宫格篇尤其）

成片出现「画面比旁白慢半拍 / 整体滞后一句」，**九成是宫格出图时格位与句序错开一格**，不是引擎、不是缓存、不是音频：切图只认版式、填图只认文件名与 `--images` 顺序、引擎只认 `src` 下标，三道环节都不校验「这张画的是不是这一句」，于是错配被固化在图片里——**重渲、清缓存、改滤镜、换编码全都改不动**。

| 时机 | 命令 | 作用 |
|---|---|---|
| 出图前 | `python scripts/panel_map.py --id <id> --panels 2\|4` | 按连续镜段把镜切成宫格段，逐格列出「格位 / 镜号 / 旁白原文 / 应画情节」，照表写提示词，错位在源头就排掉 |
| 填图后 | `python scripts/panel_map.py --id <id> --check` | 缺图、`src` 越界、`note` 还是占位、宫格服务镜段不连续、相邻两镜同图 → 退出码 1，先修再渲染 |
| 全程 | `fill_shots.py` 结尾自动刷新 `宫格对照清单.md` 并打印「镜号 \| 旁白句 \| 画面 note」 | 旁白说 A、note 写 B 一眼可见 |

清单落在 `episodes/<id>/宫格对照清单.md`，带勾验列。**逐格读旁白那一列再看画面**，对不上就重出（图名带镜号，切完用 `--images` 显式传序），不要指望重渲。相近历史场景（宫殿/城垣/船队）像素差可能很大，**像素比对不能判语义对错**，只当白边/串图参考。

## 时间轴口径（改动字幕或切点时必看）

- 片头 `HEAD_LEN = 5.0s`，与正片在 `4.2s` 交叉溶解（`JOIN_XF = 0.8`）。
- 正片内部时间 `t = 成片 t - 4.2`；字幕句子 i 在成片 `s + 5`，对应正片内部 `s + 0.8`。
- 早期版本多次漏掉这 0.8 秒，导致字幕与画面错位。
- 音频 = 片头 5.0s + 该篇 `vo.wav`；全片总长 = 5.0 + 旁白音频长。
- **无片头（`head.mode="none"`，v2.11.5）**：片头段压到 `HEAD_LEN = JOIN_XF = 0.08s`（25fps 下 2 帧），`EXIT_AT = BODY_SHIFT = 0`——正片第一帧就在 `0:00`。**故意不删片头链、不重排输入槽**（删 `[0:v]` 片头底与 `[2:v]` mask 会让后面所有固定槽（雾层/浮尘/遮罩/光斑）前移，得重建整张滤镜图）；音频只拼 0.08s 静音，不生成 `head_voice.wav`，片头字幕不挂。cues 的 `+HEAD_LEN` 自动变成 +0.08，字幕、切点、静帧时间点全部跟随，1 帧误差肉眼与听觉都无感。**注意成片总长变短约 5 秒**：`项目说明` 里的时长与"片头 5.0s"表述要按本篇改。
- 结尾针：`vo.wav` 尾部留白 3.6s（`new_episode.py` 的 `TAIL`，重跑建篇才生效）；片尾卡从「末句结束 + 0.45s」淡入，到「总长 − 0.25s」淡出，窗口约 2.9 秒。窗口 <1.2 秒时引擎警告并跳过片尾卡。
- 时间轴与画幅无关：竖版片的 `HEAD_LEN`、切点、字幕偏移、结尾窗口算法完全相同，只是画幅与版面换了。
- **顶部卷名/篇名是常驻角标（设计，不是 bug）**：`make_v12.py` 704–710 行写死两条 ASS 事件，从 `0:00` 挂到片尾卡前——`Vol` = `系列名 · 卷名`，`Title` = 篇名，`{fad(1000,900)}` 淡入淡出。`shots.json` 里没有开关；想去掉必须改引擎，须先经主人同意。

## 片头音轨规则（仅片头形态 A/B/C；选 D 无片头时整节跳过）

- 文案模板「今天讲一个{title}的故事。」写在 `shots.json` 的 `head_text`。**选 D 时 `head_text` 仍会写进 `shots.json`，只是不合成音轨、不进成片**——它可以当发布的第一句钩子或系列名用。
- **两种口型路径**（按「开工确认」第 3 项决定，仅横版有 A/B；`shots.json.head_video` 是否存在即开关）：
  - **真同步（可选，需授权花积分）**：选生成时给 `head_video` 指向本篇专属口型视频，音视频同源，嘴清晰、真张合。生成法见下。
  - **旧式换音轨（默认，零积分）**：不生成口型时不设 `head_video`，沿用当前说书人的内置口型视频（`host=ancient` 用 `talk_test.mp4`，`host=modern` 用 `talk_modern.mp4`，两者各配同人遮罩，引擎自动切换）只换本篇音轨；唇形按内置原句生成、换篇为近似对口型，但**可用于正式片**——已交付的 140/186/002 等篇即是此路径。用户要真同步时才升级到下一种。
- 音色锁定 `zh-CN-YunjianNeural`，即 v4 原说书人；与 `v4/talk_ref.mp3` 波形相关 1.0000。两套说书人（古装/现代）共用此音色，说的是本篇篇名，形象与音色无关。
- 语音起点对齐 `0.173s`，**默认不变速**，尾部留白到精确 `5.000s`；仅篇名过长、语音拖过 `2.90s` 时轻微加速 ≤1.20x。
- **本篇口型视频生成法（VideoGen，约 50–100 积分/篇，需授权）**：
  1. 先把 `head_voice.wav` 传临时公网链接：`curl -F "reqtype=fileupload" -F "time=1h" -F "fileToUpload=@<wav>" https://litterbox.catbox.moe/resources/internals/api.php`（本地路径 VideoGen 会拒：`base64 audio is not supported`）。
  2. VideoGen：`reference_images=[<技能目录>/runtime/episodes/001/v4/host_talk.png]`（锁人物）+ `reference_audios=[公网URL]`（驱动唇形）+ `seconds=5` + prompt 要求「中文口型与参考音频严格同步、保持参考人物一致、无文字水印」。`reference_images` 可以用，`image` 不能和音频同传。
  3. 产物移到 `episodes/<id>/片头口型/`，路径写进 `shots.json.head_video`；引擎槽 16 自动改读它，delogo 与遮罩链路不变。
  4. 验收：生成音轨 vs 本篇 `head_voice.wav` 相关应 >0.9、零偏移；成片音轨相关应 =1.0；嘴部帧间差明显大于整帧。
- **柔焦遮挡方案已作废**（用户否定「遮挡嘴」）：局部 gblur、压暗 12%、alpha 0.85 均已从引擎删除，不要再走回头路。
- 生成：`python <技能目录>/runtime/series/head_voice.py --episode <id>`（有签名缓存，重跑不联网）；自检 `--check-voice`。片头音轨由 `start_story.py` 建篇时自动生成，**`--head-mode none` 不生成**。

## 验证方法

### 片头转写（最硬的证据）

```bash
ffmpeg -y -v error -i test_v12_<id>.mp4 -vn -t 3.6 -ar 16000 -ac 1 head_check.wav
```

对 `head_check.wav` 做语音转写，确认念的是本篇篇名而非内置默认台词。

### 画面抽帧

```bash
ffmpeg -y -v error -ss 1.5 -i test_v12_<id>.mp4 -frames:v 1 verify.png
```

检查：标题、卷名、片头字幕文字、说书人形象是否符合题材（古装/现代）与嘴型、**片头不出现 NO. 编号**、无黑屏/错位/重影。**选 D（无片头）时另查两项**：`ffmpeg -ss 0 -frames:v 1` 第一帧必须就是正片第 1 镜（不是空镜/黑场/片头图定格），且 `-ss 0.3` 处首句字幕已出现、首句语音已开口。

### 换镜画面差异（量化）

在换镜前后各抽一帧转灰度，算主体区域（去掉下方字幕带，如 `[60:700, :]`）的平均绝对差。一镜一图约 25，一图多镜只有 5.5~6.1。低于 10 说明画面过于单一，需要换图。镜头数由本篇旁白句数决定，逐镜检查即可，不必凑满某个数量。

### 灵动效果（量化）

同一静态镜相隔 1 秒抽两帧，统计「变化 >12 的像素占比」。v12 浮尘流光约 2.9%~7.1%；若接近 0 说明只有滤镜、没有真位移的物体。

### 规格

```bash
ffprobe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 <成片>
```

目标 1920x1080 / 25fps，音频 48kHz AAC 192k，响度 -16 LUFS / TP -1.5。

## 画面运动与背景音乐

### 画面运动（内置默认）

正片每个镜头默认按画面内容自动选运镜（v2.7.0 起，见下一节）；片头说书人片段与片尾定帧卡不参与。想退回旧的「纯纵向浮动」，给该镜写 `{"move": {"auto": false}}`：**奇数镜（i=0,2,4… 即第1/3/5…镜）画面内容从上往下浮动，偶数镜从下往上浮动**，引擎用 `zoompan` 的 y 从 span→0 / 0→span 线性实现，`span = (ih-ih/zoom)*MOTION_SCALE`；为保证有富余空间，每镜静态 zoom 最低放大到 1.12。旧版**zoom 固定、x 固定**：不做推近、不做开镜脉冲、不做左右摆动/手持横向抖动、不在 y 上叠微抖；雾层与浮尘光点的 x 也固定，只做纵向浮动/上升。逐帧胶片颗粒已移除，静止区域不会闪烁。

**顺滑关键（超采样）**：`zoompan` 把 y 取整到源像素。1920x1080 上做 0.5 倍速平移时每帧位移不足 1px，实测 230 帧里仅 1 帧动 1px，肉眼看就是「停很久跳一格」的卡顿。引擎固定 `SUPERSAMPLE=3`：静帧先 `scale` 到 5760x3240，在这张 3x 画布上做 zoompan（源域每帧位移 ≥1px），再用 lanczos 缩回 1920x1080，位移就变成连续的亚像素变化。`dx` 静态取景偏移同比乘 3 保持构图。不要为省渲染时间把 `SUPERSAMPLE` 改成 1，否则卡顿必现。

**运动速度**：由引擎顶部 `MOTION_SCALE` 只缩放 y 的垂直平移幅度（现 `1.125`；`1.0` 为原速）。改这一个数即可调整旧版纵向浮动的快慢；auto 运镜的 `zoom` / `pan_x` 幅度自成一套（见下节表），要整体再快就改 `SHOT_SIZE_MOVE` / `SUBJECT_MOVE` 里的数字，别只改 `MOTION_SCALE`（它只管纵向浮动）。画面没有左右摆动/手持抖动，也没有开镜缩放脉冲。

### 可选运镜：`move` 三档（v2.5.0 起）

不写 `move` 的镜＝按 `note` 的【景别·主体】标签自动选（v2.11.3 起）。要钉死某镜就在该镜加：

```json
"move": {"type": "zoom",  "amount": 0.05, "dir": "in"}     // 推近；dir:"out" 是拉远
"move": {"type": "pan_x", "pct": 0.048,  "dir": "left"}    // 横移；pct = 目标位移占画宽比例（推荐）
"move": {"type": "pan_x", "amount": 0.45, "dir": "left"}    // 老口径：横向余量比例（无 pct 时才用）
"move": {"type": "pan_y", "amount": 0.4,  "dir": "down"}    // 纵向平移，可用 amount 控幅度
"move": {"type": "hold"}                                   // 完全不动（节奏保底，也让眼睛休息）
"move": {"auto": false}                                    // 退回旧版纵向浮动
```

| 类型 | 参数含义 | 上限 | 适用 |
|---|---|---|---|
| `zoom` | `amount` 是**绝对 zoom 增量**（如 0.05 = 1.12→1.18），auto 只用 0.04 / 0.08 / 0.12 三档 | 0.12 | 通用，最不抢戏；近景人物镜优先用它代替横移 |
| `pan_x` | `pct` = **目标位移占画宽比例**（0.048 = 4.8%），渲染时按实际 `z0` 反算 | 0.05 | 只给远景/空镜；近景人物、字幕密集的镜不用 |
| `pan_y` | `amount` 缩放 `MOTION_SCALE` 后的幅度 | 1.0 | 想要旧版纵向浮动时写它（或 `{"auto": false}`） |
| `hold` | 无参数 | — | 完全不动；每 5 镜至少一镜

**为什么横移要更保守**：字幕是横排的，背景横向一走，眼睛在“读字”和“追画面”之间来回切；纵向走与文字方向垂直，冲突小。所以横移幅度必须比纵向还小，且不给近景人物镜。

**动态镜不参与位移**：`move` 对 `motion:true` 的镜无效。素材自带运镜，再叠引擎浮动＝双重运动（晕、飘）；动态镜只做 `phase` 取帧、16:9 裁切、压暗、镜像、定时长，也不再走 3x 超采样（少一次放大再缩回，画面更锐、渲染更快）。

### 按标签自动选运镜（v2.6.0 起，v2.7.0 起默认；v2.11.3 改为读标签）

**不写 `move` 也会走这套推断**。引擎先剥掉 `（重音）` 这类括注，取 `note` 开头的 `【景别·主体】`，按 `·` 拆两段：**景别优先，主体加成，正文只兜底，都判不出就 hold**。`beat` 不参与画面判定（只在 hold 节奏层做段边界）。

| 景别（第一段） | 判定 | 参数 |
|---|---|---|
| 远景 / 大远景 / 空镜 | 横移（末镜空镜改收尾拉远） | `pan_x pct 0.048` → `zoom 0.12 out` |
| 全景 | 横移 | `pan_x pct 0.042` |
| 中景 | 缓推 | `zoom 0.04 in` |
| 近景 | 推近 | `zoom 0.08 in` |
| 特写 / 大特写 | 强推 | `zoom 0.12 in` |

| 主体（第二段） | 判定 | 参数 |
|---|---|---|
| 战斗（厮杀/交战/冲锋/攻城/突围/冲阵/列阵/夜袭…） | 强推，并把中景/近景的 zoom 往上顶一格 | `zoom 0.12 in` |
| 人群（群臣/朝会/市集/码头/营帐/街道/船坞/宴席…） | 横移 | `pan_x pct 0.042` |
| 器物（手部/奏报/金锭/印玺/刀光/书信/茶盏…） | 推近 | `zoom 0.08 in` |
| 人物（背影/侧后/跪拜/面孔/主角…） | 缓推 | `zoom 0.04 in` |

> **正文兜底顺序**：战斗 → 空镜/远景 → 其它主体；关键词全部双字以上（不再用「雪/海/刀/信/印」这类单字，单字会把「雪落宫墙」「断粮奏报」判错）。**都判不出 → `hold`**，日志打「未识别 note（补【景别·主体】）」——以前兜底是一次 0.075 缓推，看起来像正常运镜，其实 note 根本没写对。
>
> **横移现在是真百分比**：pan 镜固定 `z0=1.12`（横向余量 10.71% 画宽），`pct 0.048` 在任何 lens 上都真的是 4.8%；老写法 `amount`（余量比例）仍可用，但换 lens 后位移会变。
>
> **`hold` 优先落段落边界**：每 5 镜一静的窗口里，优先选 `beat` 变化处的第一镜，没有候选才回退窗口中点；日志会写理由与原判，如 `镜2 hold（节奏:段落收束（原判 zoom 0.12））`。

**三条节奏约束（自动套用，人工显式写 `type` 的镜不参与改写）**
1. 横移方向交替；同向连续最多 2 镜，第 3 镜强制反向；
2. 每 5 镜至少留一镜 `hold`（完全不动），给眼睛休息点；**末镜豁免**，优先收尾拉远；
3. 动态镜永远不动（`type: none`）。

**人工优先**：某镜写了显式 `type`（`zoom`/`pan_x`/`pan_y`/`hold`），那镜不会被 auto 改写，也不参与上面的方向交替与 hold 配额计算（配额只在 auto 镜里找替身）。所以「某镜莫名变成 hold」不是 bug，是第 5 镜配额在找最近的一镜；想固定它就写 `{"type":"zoom","amount":0.04}`。

**`note` 必须规范**：以「【景别·主体】」开头，如 `【远景·海上船队】黎明宝船列队出海`、`【特写·手部器物】朱笔压在奏报上`、`【空镜·雪后宫墙】无人物，留白收束`。写得含糊（只有“和珅在府库”这种）会同时命中“人物”和“银箱”，判定就不可控——**标签是 auto 的唯一输入，正文怎么写随你**。

### 动态镜的配段规则（v2.4.0 起）

引擎本身允许一段素材服务多镜（`resolve_srcs()` 对同段引用 `split=N`，各镜按自己的 `phase` 去 `trim`），但**真动态藏不住重复**：两镜同源时观众看到的是同一机位、同一动作、同一段运镜重播，比静态图重放显眼得多。所以技能层收紧为：

1. **默认一镜一素材**——一个 `motion:j` 只服务一个镜。`fill_shots.py --dynamic-at 2,5,9` 若只给了 2 段素材，会直接报错并列出「要么补素材、要么把镜 9 改回静态」；
2. 两种例外才加 `--reuse-motion`：① **同一动作拆相邻两段**（镜号相邻、phase 首尾相接、两镜间不加转场花样）；② **环境连续体延展**（烟/火/雨/人流/船队），要求两镜**景别不同** + 镜像/压暗/裁切至少再变一项 + `note` 写「同素材延展」；
3. 放行后 `phase` **顺序相接**（按 `caption.srt` 句长累加，后一镜从前一镜结束点起算），不再 1.5 秒等距乱铺；phase 逼近/超过素材时长会打印警告（那等于从头重放）；
4. 素材不够时宁可把多出的镜改回静态图——别用一段素材反复充数。动态素材约 50~100 积分/段，所以这条规则的前提是**动态镜别排多**（开工确认第 5 项默认 0 个）。

## 渲染提速与开关（2026-11-18）

引擎 `runtime/episodes/001/v12/make_v12.py` 新增以下开关，默认值即推荐值：

| 开关 | 说明 |
|---|---|
| `--cache` / `--no-cache` | 分镜缓存：每镜单独渲成 mp4 存 `episodes/<id>/缓存/镜头/`，命中即复用；改字幕、换片头底图/音轨都不失效，只有素材、lens、时长、相位、运动参数变了才重渲 |
| `--encoder libx264/qsv/auto` | `qsv`=Intel 硬件编码；`auto`=有 QSV 就用。实测编码只占整链路约 2s，故默认仍 libx264（画质与旧版一致） |
| `--ss 1~6` | 超采样倍数，默认 3。源域仍 3x 放大保证每帧位移 ≥1 源像素，zoompan 直接输出 1920x1080（旧做法输出 5760x3240 再缩回，白算 9 倍像素）。1 会阶梯卡顿，不建议 |
| `--legacy-render` | 一次性回退到旧实现（5760 输出 + lanczos、全分辨率浮尘/雾渐变），仅用于对照 |

`shots.json` 支持 `"render": {"cache": true, "encoder": "libx264", "ss": 3}`，由 `start_story.py --profile fast|quality` 写入；命令行开关优先于本篇配置。

- `--profile fast` = 缓存开 + libx264 + 3x（画质与默认逐像素级别一致，只是不再重渲镜头）
- `--profile quality` = 缓存关 + libx264 + 4x 超采样
- 实测（20s 测试片、同内容）：老链路 56.5s → 新默认 36.1s → 新+缓存命中 22.7s；新旧 SSIM 0.995 / PSNR 39.7dB

## 宫格出图：两宫格 / 四格（省积分，2026-11-18 起内置支持）

逐镜单图最可控，但每镜一次出图。宫格图一次出 2 格或 4 格，用 `scripts/split_panels.py` 切成单镜图后照常填图，引擎不需要任何改动。**默认走两宫格（v2.11.0，开工确认第 7 项推荐值）**。**出图前先跑 `scripts/panel_map.py --panels 2|4` 排「格位↔镜号↔旁白原文」清单**（见「画面情节与旁白句对位」），照清单逐格写提示词——宫格最贵的错误就是错开一格，成片整体滞后一句还查不出来。切完必须 `panel_map.py --check` 退出码 0 + 逐格勾验「这一格画的是不是这一句」才许渲染。

| 方式 | ImageGen 画布 | 每格尺寸 | 切分后（16:9） | 切分后（9:16，加 `--format 9:16`） |
|---|---|---|---|---|
| 单图 | 1536x1024 | — | 顶部裁 16:9 → 1920x1080（1.25x） | 出 1024x1536 原生竖图直接用 |
| **两宫格·左右（默认）** | 2048x768 | 1024x768 | 每格裁 16:9 → 1920x1080（1.875x） | 居中裁 576x1024 → 1080x1920 |
| 两宫格·上下 | 1024x1536 | 1024x768 | 同上 | **不用于竖版**（4:3 横构图切 9:16 会切没主体） |
| 四格 | **2048x1152** | **1024x576（原生 16:9）** | 每格直接放大 1.875x → 1920x1080 | 每格居中裁 324x576 → 1080x1920（3.33x，明显发虚，竖版别用四格） |

> **四格画布为什么从 2048x1536 改成 2048x1152（v2.11.4）**：Seedream 按出图像素分档计价，**261 万像素是一道坎**（≤ 261 万与 > 261 万差一倍）。2048x1536 = 315 万，刚好跨档；2048x1152 = 236 万，留在低价档，而每格切完仍是 `1024x576` → 1920x1080，**输出像素一模一样**（旧画布是 1024x768 再裁成 576，多一道裁切、多花一倍钱）。代价：每格没有 4:3 的上下余量，提示词要写「每格主体居中偏上、上下留余量」，主体画太满会切头。`split_panels.py` 按画布动态算格宽，脚本不用改（实测 2048x1152 四格 → 4 张 1920x1080，内容占比 100%）。

**竖版宫格的正确做法**：画布仍用**横版**（`1536x1024`，左右两格各 `768x1024` 竖构图），每格主体压中轴、上下留余量，切分加 `--format 9:16` → 每格居中取宽 `576x1024` → 放大 `1080x1920`（1.875x）。这样既不拉伸也不切头；用竖画布上下叠两格脚本会直接拒绝。

**命名与重出映射（必守）**：宫格图文件名按**镜号打头**（`s07_饭局.png`），切完是 `s07_饭局_p01/_p02`，`fill_shots.py` 按文件名排序正好对上镜号。重出的图放 `重出/`、改名 `s07_饭局_v2.png`，切完用 `--images` **按镜号顺序显式传入**——丢回 `--grids-dir` 会按名字重排，静默错配镜号（出图前最好先在 `导演稿.md` 把「镜号 ↔ 画面」钉死）。

**提示词写法**（两宫格示例，四格同理）：先写风格句，有人物的篇紧跟一句「人物锚定句」，再写「画面横向均分为左右两格，无格线无边框、两格铺满整张画布；左格：<镜 1 情节>；右格：<镜 2 情节>；两格为同一场景的连续两个镜头，光线与色调一致」，并尽量让**一格有人、一格环境/器物**（见上「主人翁出镜节奏」）。宫格出图最容易出的问题：格线/白边、两格人物串位、格内构图太满导致裁 16:9 切掉头。建议每格**主体偏上、下方留白**。

**防"模型自己加字"**：基底句里的"无文字"不够用，出图前先列出这个场景里**天生带字**的物件，直接换成无字同类：座位牌/名牌 → 空白卡 + 模糊色块；牌匾/门额 → 只留浮雕不写字；书页/奏折 → 留白或墨迹虚化；幡旗/招牌 → 纯色纹样。提示词再加一句「画面中不得出现任何文字、字母、数字、字符、招牌字迹」。真出了字只能重出（花积分），所以宁可提前换道具。

**切分**（宫格原图放 `原图/`，不要放进 `场景图/`）：

```bash
python scripts/split_panels.py --grids-dir "episodes/<id>/原图" --panels 2 --out "episodes/<id>/场景图"
python scripts/split_panels.py --images g1.png g2.png --panels 4 --layout 2x2 --out "场景图/"
python scripts/split_panels.py --grids-dir "原图" --panels 2 --dry-run   # 只看切分参数不写盘
```

- `--panels 2` 按图比例自动判版式：宽图（≥1.2）→ 左右两格 `1x2`；竖图（≤0.85）→ 上下两格 `2x1`；接近方形会报错，用 `--layout` 指定。**`--format 9:16` 时只认横画布**（竖画布直接报错并给指引）。
- `--format`：`16:9`（默认，切 `1920x1080`）/ `9:16`（切 `1080x1920`，每格**居中取宽**，主体压中轴）。
- `--panels 4` 固定 `2x2`，阅读顺序 左上→右上→左下→右下。
- 每格先做**非白外接框检测**再去白边（`WHITE=245`，只有宽度/高度不足格子 10% 才回退整格），再去 16:9（`--anchor top` 默认贴顶，与单图流程一致；`--anchor center` 居中）。
- 输出 `<原名>_p01.jpg …`，按阅读顺序命名 → `fill_shots.py` 按文件名排序正好对上镜号。
- 打印里 `内容占比 <55%` 会标「[注意] 可能有白边」，**必须抽帧看四角**。
- 切完照常 `fill_shots.py --images-dir "episodes/<id>/场景图"`，`run_episode.py --grids-dir "原图" --panels 2` 可一键切分+建篇+填图。

成本参考：13 镜一镜一图 → 两宫格 7 次出图（比 13 次省近一半）；30 句上限的篇 → 两宫格 15 次、四格 8 次。4 格更省但串图/白边风险更高，默认两宫格。

## 片头/封面专属图（2026-11-18 起：一图两用）

**为什么必须单独出**：片头底图若从 `场景图/` 里挑，无论挑哪张都会与正片某一镜重复（`g06` 既当片头又在第 5 镜），观众一眼看出「开头就是第几镜」。所以每篇额外出**一张 16:9 横图**：横图直接做片头底图，再从这张横图纵向裁一条 2:3 做三平台封面（不再出两宫格）。

**出图规格**：`2048x1152`（16:9），同一人物 + 同一场景，风格句照旧。构图约定：

| 要求 | 原因 |
|---|---|
| 人物中远景、全身或大半身，高约占画面 55%~70% | 封面要纵向裁 2:3，只给半身大头会裁成「只剩脑袋和胸口」 |
| 人物偏左三分之一 | 右侧 1/3 是说书人位（引擎贴右侧合成），也给封面裁切留余量 |
| 右侧留天空/海面/船帆等留白 | 说书人叠上去不压住主体 |
| 顶部留片名位，底部留甲板/地面暗部 | 标题卡压顶部，底边要裁 6% 去平台水印 |

**人物怎么画**——这条最容易返工：片头若仍用说书人（A/B），图里的人物**必须背影或侧后、且袍色与说书人（暗红）区分开**，否则同框像两个红衣主角并排。选 C（无人像）时可让主角侧脸，但也不做正脸大特写。实测「红袍正面 + 说书人」不可用；「深青袍背影 + 说书人」成立（说书人像站在他身后讲故事）。

**切分**：

```bash
python scripts/head_cover.py --image "episodes/<id>/原图/片头图_横.png" --episode-dir "episodes/<id>"
# -> episodes/<id>/片头图/head_16x9.jpg（1920x1080，横图本身，底部裁 6% 去水印）
# -> episodes/<id>/片头图/cover_2x3.jpg（1024x1536，从横图纵裁）
```

- `--cover-x` 是纵裁锚点：`0` 贴左、`0.5` 居中、`1` 贴右，默认 `0.30`（配合「人物偏左三分之一」）。裁出来人不在中间就往对应方向调。
- `--trim-bottom` 默认 `0.06`，切掉底部水印带；源图水印位置不同就调大，水印已不可见设 `0`。
- 只裁不拉伸；源图若不是 16:9 会按 16:9 居中裁（两侧会掉一点），切完必须目视 `head_16x9.jpg` 与 `cover_2x3.jpg` 两张。
- 生成侧就是 16:9，所以不需要再像宫格那样算取景带；横图比例小于 1.4 会被脚本直接拒绝。

**接进本篇**：`shots.json` 的 `head_image` 写 `片头图/head_16x9.jpg` → 重跑 `write_director_doc` 刷新导演稿 → 重渲（分镜缓存会全部命中，只重烧片头与合成）。封面：

```bash
python scripts/make_cover.py --root "<root>" --episode-dir "episodes/<id>" \
    --image "episodes/<id>/片头图/cover_2x3.jpg" --platform douyin --kicker "<kicker>"
# 小红书同上；B 站 16:9 改用 --image ".../片头图/head_16x9.jpg"
```

**片头形态 C（无人像）怎么落**：`shots.json` 写 `"head": {"mode": "title", "voice": true}`（或 `start_story.py --head-mode title`）。`voice:true` 保留口播与片名字幕、片头长度按语音自适应（约 2.4~3.6s），此时标题卡直接压在片头图上；`voice:false` 才是纯静音，默认不用。C 只影响片头，正片与时间轴由引擎按 `HEAD_LEN` 变量自动换算，但每篇仍要复核字幕起点与结尾针窗口。

**片头形态 D（无片头）怎么落（v2.11.5）**：`shots.json` 写 `"head": {"mode": "none", "len": null, "voice": false}`（或 `start_story.py --head-mode none`）。引擎把片头段压到 0.08s（2 帧）、`EXIT_AT=0`，正片第一镜从 `0:00` 起；不生成 `head_voice.wav`、不挂片头字幕、片头底图不参与合成（`head_image` 留着也不影响画面）。**别手动把 `head` 整块删掉**——删掉等于回到默认 `host`，引擎会去合成说书人口播、还要 5 秒素材，反而报错或出成有片头。这张 16:9 横图在 D 下不废弃：

```bash
python scripts/head_cover.py --image "episodes/<id>/原图/片头图_横.png" \
    --episode-dir "episodes/<id>" --cover-only
# -> episodes/<id>/片头图/cover_2x3.jpg（1024x1536）；不出 head_16x9.jpg
```

D 的取舍要跟用户讲清：**正片多出约 5 秒有效时长（30 秒片等于 +20%），但失去“今天讲一个…”的系列辨识度**，那 5 秒是唯一固定人物 IP 露出的位置。所以 D 下首镜必须本身有开场感（不是过渡镜）、建议 ≥2.5s、运镜别落 `hold`；封面与片尾定帧卡承担系列识别。
